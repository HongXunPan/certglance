# 工程代码技术选型

## 项目定位

本子仓从零构建 CertGlance，一款 macOS 原生 TLS 证书到期小组件。系统小组件是主要展示入口；宿主 App 只负责域名管理、主动检查与通知授权，不另造一套完整看板。

## 技术栈与边界

- 目标平台为 macOS 26 起。仅在无需大兼容层时考虑向前兼容；当前工程不承诺旧系统支持。
- 使用 Swift 6、SwiftUI、WidgetKit、Security.framework 与 UserNotifications，不引入第三方依赖。
- 使用正常的 SwiftUI `WindowGroup`、系统 `List`、`Form`、`Button`、`Alert` 和 SF Symbols；不模拟窗口、菜单或系统通知。
- Widget 时间线请求约每 12 小时更新一次，实际执行由 WidgetKit 决定，不承诺准点或每天必达。扩展可在生成时间线时做限时网络检查；手动刷新由宿主 App 发起。
- 通过系统 TLS 信任对象读取叶子证书截止时间，不绕过服务器证书校验，也不把 HTTP 状态当作证书状态。

## 数据与通知

- 域名列表、证书快照、通知去重记录通过共享仓储接口读写。首个适配器使用 App Group `UserDefaults`；这是功能开发态方案，**不代表 Mihomo Meter 式自签名分发已可用**。
- 当前 Bundle ID `com.HongXunPan.SSLWidget` 与 App Group ID `group.com.HongXunPan.SSLWidget` 为开发态占位；正式分发前须确认稳定身份并验证迁移及共享访问。
- 宿主 App 请求通知权限。每次成功读取证书后，根据截止时间规划默认 30／7／1 天本地提醒；已进入提醒窗口的首次检查仅提醒一次。同一证书截止时间与同一提醒档位去重。
- 扩展按时间线更新快照及提醒；若系统不运行时间线、用户关闭通知、共享容器不可用，提醒无法保证准时。应用启动及主动检查会重新同步。
- 用户可从看板看到检查时间、连接失败、证书不受信任和已过期状态。失败时保留已知截止时间，不把网络失败误报成健康。

## 默认执行规则

- 本项目代码实现使用 `macos-native-ui-engineer`，涉及视觉时同时使用 `ui-ux-pro-max`；系统语义与 Apple 官方文档优先于通用 Web 或移动端模板建议。
- 最小验证：`plutil -lint` 检查工程与 plist；`xcrun swift format lint --recursive --strict` 检查 Swift；`xcodebuild` 做 macOS 无签名构建。构建不能代替安装、WidgetKit 调度、App Group 权限或系统通知验收。
- 若官方 API、证书链、扩展沙盒、共享存储、签名身份与代码前提冲突，立即停止并重新规划，不静默添加兜底或将静态通过宣称为运行态通过。

## 分发边界

后续分发遵循 Mihomo Meter 的规则方向：固定自签名身份、按架构提供 DMG、GitHub Releases 与 Sparkle 更新；不复用其 Bundle ID、证书或更新密钥。

当前仅为独立假数据文件桥接 PoC 提供手动 GitHub Actions：使用 SSL Widget 专用固定自签名证书、签名宿主和 Widget、生成非公证 DMG 及静态核验报告。该工作流不发布 GitHub Release，不为正式应用签名，也不引入 Sparkle。版本 2 的宿主写入、Widget 读取已获实机确认；版本 3 的 Widget 写回、宿主核对仍待签名安装验收，不能据版本 2 结果推断正式分发可用。正式应用目前仍使用开发态 App Group 仓储；迁移须以双向 PoC 运行态通过为前提。
