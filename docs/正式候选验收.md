# CertGlance 正式功能候选验收

## 交付边界

本候选仅支持 macOS 26 起，包含 Intel 与 Apple 芯片切片。它使用项目专用自签名证书，但**没有 Apple Developer ID、公证或自动更新**。小组件是主要看板；宿主 App 管理域名、执行主动检查并请求通知权限。WidgetKit 约每 12 小时请求一次新时间线，未检查完全部域名时会请求约一小时后继续；剩余天数变化会预排到时间线，但实际显示和网络检查时刻由系统决定。无桌面组件、系统未调度、网络中断或通知被禁用时，无法保证到期提醒准时送达，不应作为唯一生产告警。

独立假数据 PoC 和正式 CertGlance 的 Bundle ID、数据目录、Widget 种类均不同。PoC 的实机共享结果不能代替本候选验收。

## 获取与首次安装

1. 从仓库的手动 [CertGlance 打包工作流](../.github/workflows/certglance.yml)下载对应运行的 `certglance-<序号>` Artifact，解压后核对 `SHA256SUMS` 与 `CertGlance.dmg`。工作流不自动创建 GitHub Release。
2. 打开 DMG，把 `CertGlance.app` 拖入“应用程序”。这是首次安装入口；**不要用 Finder 覆盖已安装的 CertGlance**，因为现阶段没有通过“原桌面组件位置保留”的升级验收。
3. 首次打开非公证自签名 App 可能被 macOS 拦截。确认来源和校验和后，按 [Apple 官方指引](https://support.apple.com/zh-cn/102445)在“系统设置 → 隐私与安全性”选择“仍要打开”。不要全局关闭 Gatekeeper，也不要运行删除隔离属性的命令。
4. 打开 App，点击工具栏“＋”，在原生弹窗中输入域名、`域名:端口` 或带路径的 HTTPS 网址，再点击“添加端点”；443 与其他端口是不同监控对象。首次添加后看板会确认添加并检查该端点。需要到期提醒时，点击“开启通知”并在系统弹窗中授权；若此前已拒绝，按看板指引到系统设置开启。
5. 在 macOS 桌面小组件图库中添加“CertGlance 证书到期”的小、中或大尺寸。自动小号聚焦最紧急域名，中号最多显示三个风险展示项，大号最多显示六个风险展示项及其余数量；一个同日组可能代表多个端点。再添加两份“固定证书端点”小号，在系统编辑界面分别选择不同端点。

## 静态核对

从工作流下载的三件文件放在同一目录后，可在该目录运行：

```sh
shasum -a 256 -c SHA256SUMS
```

挂载 DMG 后还可用系统 `codesign --verify --deep --strict --verbose=2` 检查 `CertGlance.app`。这些步骤只证明下载内容及签名结构，**不证明 macOS 已运行 Widget、共享了数据或投递了通知**。

## 开发期视觉预览

在源码子仓运行 `bash scripts/render-visual-previews.sh`，可用固定的假数据离屏生成主界面内容与自动小／中／大号、固定小号 PNG。预览覆盖浅／深色、长域名、失败／过期、数据待更新和超出展示上限，以及大号 1／3／5／6 个端点；输出留在子仓 `.codex-tmp/certglance-visual-previews/output/`，不读取真实域名或系统配置。每次修改版式后应查看图片，再做下一轮调整。

离屏渲染不能呈现原生 `Menu`／`List` 的完整外壳，也不等同 WidgetKit 的真实边距与图库效果。发布前仍按下文在桌面实机验收，不能以 PNG 或构建通过代替。

同日到期验收需覆盖两个可信端点合并、异常端点不合并、跨日端点不合并，以及中／大号日期组的域名可读性；固定小号仍只显示所选端点。设置验收需从应用菜单和 `⌘,` 打开原生设置窗口，增删提醒天数后复核待发通知更新、已错过新档位不补发、各端点通知仍独立。设置和通知投递的实机结果不得由模型检查或离屏预览替代。

## 首台 Mac 的运行态验收

按以下顺序逐项记录，不用一个静态结果替代下一项：

1. 宿主启动、域名添加和真实 TLS 检查：选择一个当前有可信 HTTPS 证书的域名，看到截止日期、剩余天数和检查状态；再使用可控的失败域名，确认错误不会显示为“正常”。网络结果依赖执行时的证书和 DNS，不作为固定值断言。
2. 文件桥接：添加域名后，检查当前账户 `~/Library/Application Support/com.HongXunPan.CertGlance/config/domains.v1.json` 和 `state/snapshots.v1.json` 已生成；不要手工编辑或公开这些文件。正常权限为目录 `0700`、文件 `0600`。
3. WidgetKit：图库能找到自动小／中／大号及固定小号；它们读取的是刚添加的真实域名与证书状态，不是 `example.com` 占位数据。两份固定小号应分别保持所选端点；删除其中一个端点后，该组件须提示重新选择，不能暗中切换到另一端点。核对剩余天数与到期日期同时显示、状态相符；中号最多显示三个展示项，大号最多显示六个展示项，日期组内的端点和未展示端点均应计数准确。较多域名可分批更新，多实例不应把待检队列即时连发为多批；宿主主动检查仍覆盖全部。小组件刷新后如显示错误，回到 App 主动检查并查看错误信息，不删除原始数据。
4. 通知：系统授权状态显示为已开启；对受控的即将到期证书验证对应 30／7／1 天提醒规划和实际系统投递。仅看到授权成功或定点模型测试通过不算投递通过。
5. 生命周期：关闭宿主窗口或退出宿主后，原桌面组件仍在原位置；等待系统刷新时，记录实际时间和是否出现新快照，不把“12 小时”当作准点承诺。
6. 视觉与交互：分别检查自动小／中／大号与固定小号的浅色、深色、长域名、检查失败、已过期、数据待更新和 VoiceOver 朗读；大号端点数量为 1、3、6 及超过 6 时都应保持清晰。宿主日期组的“查看各端点详情”和单证书的“证书详情”须显示箭头，鼠标点击整行与键盘激活均可展开、收起，VoiceOver 能读出状态。中／大号可信未过期行的数字应完整落在静态圆徽记内、日期仍可读；同日组应朗读“最短剩余”，圆徽记不应被解释为证书有效期比例。异常行直接显示文字状态，不能显示无意义的破折号或伪圆环，跨年到期日应写明年份。离线渲染预览只能筛版式，不能代替桌面实机效果。
7. 回归：宿主启动时只检查满 12 小时的端点，新增端点不重查其他端点；检查失败时看板能区分最近检查、最近成功与连续失败次数。用隔离测试数据验证损坏配置不会被新增端点覆盖；通知 30／7／1 天档位投递后再次同步不应重复提示。静态模型检查不能替代系统通知投递验收。

任一项失败时停在当前层级，保留输入和原数据；不要重复拖拽覆盖、清空系统 Widget 数据库、全局重启系统服务或将 PoC 修复助手用于正式应用。

## 已知限制

- Finder 拖拽覆盖升级曾在独立 PoC 上导致 macOS 移除原桌面组件；正式应用未验证升级保留位置。当前 DMG 仅作为首次安装候选。
- 自签名专用文件例外不是 App Group，也不是 Apple 承诺的长期共享接口；同一用户下的其他进程可访问该用户自己的数据目录。
- App Group 开发态数据不自动迁移；此前未发布正式 App，少量开发态数据请重新录入。
- 没有后台常驻进程或精确告警服务。无组件时不会仅凭安装包持续检查证书。
